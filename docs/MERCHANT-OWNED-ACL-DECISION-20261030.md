# Merchant-owned administration and access — 30 October 2026

Direct user clarification supersedes the earlier request for the developer to nominate Support managers:

- Each merchant/store owner controls their own Core staff permissions from their administrative panel.
- The owner may grant or withhold access for Marketing, Sales, Customer Support managers and other staff. A staff member's job title does not itself grant permission.
- Assignments and permission changes must be isolated to that store and audited. Core must enforce access on the server as well as in the interface; storefront/theme access is not staff authority.
- The developer does not collect a fixed global manager list, nominate another merchant's managers or automatically grant Support approval access to all Shopify staff.
- Access management and adjustment approval are distinct from executing a Shopify refund or credit. Existing financial and native-operation safeguards remain required.

The user confirmed that the existing administrative prototype is to be reviewed for Shopify compatibility after the 15-point functional work. Reference: https://vary-canvas-28139058.figma.site . It has not been treated as a working Core authorization implementation or as permission to start a replacement Admin UI now. The earlier customer/Core → architecture audit → Admin UI phase gate remains in effect.

The current Support inbox is a default-off read-only development screen; it does not yet implement the future merchant role editor or authorize approvals. No staff assignment, new access grant, production change or financial action was made for this clarification.
